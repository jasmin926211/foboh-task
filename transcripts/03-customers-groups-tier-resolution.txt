# Customers, Customer Groups & Specificity-Based Price Resolution

## Context

Currently, pricing profiles use a free-text `customerName` string field. The user wants:
- **Customer** and **CustomerGroup** as first-class DB entities
- Profiles can target a **specific customer**, a **customer group**, or **all customers**
- Price resolution uses a **6-tier specificity strategy** ("most specific wins")
- A new `GET /api/resolve-price?customerId=X&productId=Y` endpoint that returns the winning price with full reasoning

## Specificity Tiers (Most Specific Wins)

| Tier | Target | Scope | Example |
|------|--------|-------|---------|
| 1 (highest) | Customer | Selected products | "Bondi Cellars gets $22 on Koyama Brut" |
| 2 | Customer | All products | "Bondi Cellars gets 10% off everything" |
| 3 | Group | Selected products | "Premium Buyers get $5 off Koyama Brut" |
| 4 | Group | All products | "Premium Buyers get 5% off everything" |
| 5 | All Customers | Selected products | "$2 off Koyama Brut for everyone" |
| 6 (lowest) | All Customers | All products | "3% off everything for everyone" |

Within the same tier, the **most recently updated** profile wins. If no profiles match, the base price is returned.

## Step 5 — Specificity-Based Price Resolution

**File:** `packages/backend/src/services/pricingProfile/index.ts`

Rewrite `resolvePrice(productId, customerId)`:
1. Look up customer and their group memberships
2. Find all published profiles that could apply:
   - `customerId` matches this customer
   - `customerGroupId` matches any of the customer's groups
   - Both null (targets all)
3. For each profile, check product coverage (scope=all OR product in profileProducts)
4. Assign tier (1-6) based on target type + scope
5. Sort by tier ASC, then updatedAt DESC
6. Winner = first in sorted list
7. Return: `{ productId, productTitle, basePrice, newPrice, appliedProfile, tier, tierLabel, reason, candidateProfiles, rejectedProfiles }`
